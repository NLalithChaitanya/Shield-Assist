# Shield Assist — AI Dispute Resolution Copilot for Razorpay Merchants

> Track 02 — AI Risk Manager  
> Sub-problem — Chargeback Evidence Responder

Shield Assist is an AI-powered dispute resolution copilot that helps Razorpay merchants respond to payment disputes more effectively. It combines ML-based win probability scoring, deterministic safety gates, evidence intelligence, and a grounded AI copilot — always under human control.

## Architecture

```
Razorpay Webhook / Simulator
       ↓
  Webhook Verification (HMAC-SHA256, raw body)
       ↓
  Case Creation + Idempotency (event-level + dispute-level)
       ↓
  Evidence Upload → Razorpay Documents API → doc_* IDs
       ↓
  Gemini OCR → Structured Facts (per-document, traceable)
       ↓
  Evidence Intelligence:
    ├── Completeness scoring (required slots per reason code)
    ├── Quality scoring (Laplacian variance blur detection)
    └── Consistency scoring (cross-document contradiction detection)
       ↓
  ML Win Probability (calibrated GradientBoostingClassifier)
       ↓
  Deterministic Safety Gate (PREPARE / REVIEW / LOW_PRIORITY)
    ├── All conditions must pass simultaneously
    ├── Probability alone cannot override
    └── LLM NEVER makes the gate decision
       ↓
  Grounded AI Copilot (Gemini, with citation integrity check)
       ↓
  Human Approval (mandatory, auditable)
       ↓
  Contest Request Builder → Razorpay Contest API
       ↓
  Full Audit Trail (immutable, queryable)
```

## ML Methodology

### Training Data

- **3,000 synthetic disputes** generated by `data/synthetic_generator.py`
- **Split**: 2,100 train / 900 test (70/30 stratified)
- **Features**: amount, num_documents, num_required_slots, completeness, quality, reason_code (one-hot)
- **Deliberately excluded** from classifier features: consistency, contradiction_count, missing_slot_count (these are gate signals, not classifier signals)

### Ground Truth

Label generation uses a **rule-based threshold** with **8% stochastic outcome noise**:
- Strong evidence (≥90% completeness, ≤15% degraded, no contradictions) → win (with noise flip)
- Weak evidence → loss
- The noise models real-world bank discretion uncertainty

### Calibration

- Isotonic regression calibration on the classifier's probability outputs
- Brier score: 0.0923 (after calibration)
- ECE: 0.0247 (after calibration)

### Safety Gate

The gate requires ALL conditions simultaneously:
- `win_probability ≥ 0.5` (data-derived threshold from validation split)
- `completeness ≥ 90%`
- `consistency ≥ 90%`
- Zero unresolved contradiction flags
- All required evidence slots present

### False-Positive Cost Model

- Flat per-case FP cost: ₹250 (ops time + fees)
- Reputational penalty: ₹50,000 if FP rate among predicted-win cases > 15%
- Minimum reliable sample size: 20 cases
- FN cost: full disputed amount (foregone revenue)

### Key Insight

The safety gate achieves **higher precision (91.0%)** than the classifier alone (77.6%) because it combines multiple independent signals. This is the evidence for why the gate uses probability AND completeness AND consistency AND contradictions together.

## Adversarial Safety Tests

23 automated tests proving ML probability alone cannot override safety:

| Case | Input | Expected | Result |
|------|-------|----------|--------|
| A | High prob + complete + consistent | PREPARE | ✓ |
| B | High prob + incomplete | BLOCK | ✓ |
| C | High prob + contradictions | BLOCK | ✓ |
| D | Below-threshold prob + complete | NOT PREPARE | ✓ |
| E | Low prob + complete | LOW_PRIORITY | ✓ |
| Edge | Boundary values | Correct behavior | ✓ |
| AI | AI cannot self-approve | Blocked | ✓ |

## Evidence Integrity Mode

The AI copilot can only reference facts that have been:
1. Extracted from merchant-uploaded documents
2. Stored in `extracted_facts` table
3. Verified against `fact_id` and `document_id`

If the model references a nonexistent fact → draft is rejected.

Automated tests verify:
- Citations to nonexistent facts → rejected
- Document ID mismatches → rejected
- Valid citations → accepted

## Human Approval Boundary

| AI Can | AI Cannot |
|--------|-----------|
| Explain | Autonomously submit |
| Investigate | Bypass the gate |
| Identify gaps | Override contradictions |
| Recommend | Fabricate evidence |
| Draft | Approve its own response |

Contest submission requires:
1. Draft exists
2. `human.approved` audit event
3. Status = "ready"

## Known Limitations

1. **Contest API not E2E verified in Test Mode** — Razorpay Test Mode does not provide merchant-created disputes, so contest submission cannot be fully tested. The Contest API client is implemented and will function in Live Mode.

2. **Gemini free tier** — Occasional 503 UNAVAILABLE errors are handled by the resilience wrapper (retry + circuit breaker). The copilot degrades gracefully to template-based drafts.

3. **Synthetic ML data** — The classifier is trained on synthetic disputes, not real merchant data. Metrics reflect synthetic evaluation, not production performance.

4. **SQLite** — Single-process database. Suitable for hackathon demo; production would use PostgreSQL.

## Security

- Credentials loaded from environment variables, never hardcoded
- `.env` is gitignored
- API keys/secrets never exposed in API responses
- Webhook signatures verified with constant-time comparison
- Logs never contain credential values
- Contest submission has dry-run mode (`CONTEST_DRY_RUN=true`)
